Accepted by Munir 2026-11-24 (Clarify gate, T1.6/T1.7/T1.8/T1.10; mcp 2.3.0):
- Token endpoint takes both post and Basic: client record is `client_secret_post`; `app.TokenForm` moves a Basic header into the form before the SDK reads it.
- Scope `workspace` (required_scopes) plus `offline_access` listed in AS metadata; every access token must carry `workspace`; a refresh that drops it gets `invalid_scope`.
- Return address fixed in code (Claude's callback); a local trial alone may use one exact http loopback address, refused unless the issuer is http on loopback.
- No Origin allowed on /mcp in production.
- Tools return plain-text `CallToolResult` (no outputSchema/structuredContent); list_repos answers in prose, empty included.
- R-7.4 covers the SDK's own unknown-tool / bad-argument answers (rewritten by a ServerMiddleware).
- Bad client auth on refresh -> 401 invalid_client; R-6.5's invalid_grant applies once the client is authenticated.
- `app.build` refuses a config with other than one user (D-12).

**Why:** settled at the gate so later reviews do not reopen them.
**How to apply:** treat these as decided; raise only if the real client (Phase 2) contradicts one. See [[sdk-2-3-0-facts]].
